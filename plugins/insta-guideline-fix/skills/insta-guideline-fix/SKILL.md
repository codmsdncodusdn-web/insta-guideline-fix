# 인스타 가이드라인 수정 `/insta-guideline-fix`

릴스 스크립트, 영상, 카드뉴스를 받아 규정에 걸리는 부분을 찾고, **내용의 힘은 살리면서 규정에 맞게 고친 수정본**을 준다. 결과의 중심은 경고 목록이 아니라 수정본이다.

**삭제 알림이나 계정 문제를 직접 말할 때만** [references/takedown.md](references/takedown.md)를 읽고 그 절차를 따른다. "삭제됐는데 대본 고쳐줘"처럼 섞인 요청은 수정본을 먼저 주고, 진단이 필요하면 알림 문구를 보내 달라고 한 줄만 덧붙인다. 제목만 바꾼 재업로드나 새 계정처럼 회피를 요청하면 거절과 이유를 먼저 쓴다.

메타는 판단 기준을 전부 공개하지 않고 자동 시스템이 오판하기도 하므로, 수정본도 안전이 보장되지는 않는다. "안전합니다" 대신 "찾은 위험은 이것입니다"라고 말한다.

## 1. 입력 읽기

없는 항목은 되묻지 말고 결과에 "못 본 것"으로 적는다. 점검할 원고 자체가 없을 때만 물어본다.

| 형식 | 읽는 법 |
|---|---|
| 릴스 스크립트 | 제목(상단 문구), 훅, 나레이션, CTA, 캡션을 구분한다 |
| 카드뉴스 텍스트 | 슬라이드별로 나눈다. 번호가 없으면 순서대로 매긴다 |
| 카드뉴스 이미지·PDF | 슬라이드를 한 장씩 직접 본다. 이미지 속 글자, 캡처, 사진, 로고, 버튼 모양까지 확인한다 |
| 릴스 영상 | 프레임을 뽑아 직접 본다. 위반은 말보다 화면에서 자주 나오므로 영상 끝부분까지 본다. 나레이션은 사용자가 준 대본이나 받아쓰기 도구의 결과로 읽는다 |

```bash
ffmpeg -i "<영상>" -vf "fps=1/2,scale=540:-1" "<작업폴더>/check_%03d.png"
```

FFmpeg가 없으면 설치를 요구하지 말고, 대본과 주요 장면 캡처를 달라고 한 뒤 받은 범위만 점검한다. 대본과 받아쓰기 도구가 모두 없으면 프레임 점검은 계속하고, 듣지 못한 것을 "못 본 것"에 적는다. 무음에 가까운 영상에서는 받아쓰기가 "감사합니다." 같은 없는 말을 만들 수 있으니, 짧은 결과가 의심되면 소리 크기를 확인하고 그 내용을 근거로 쓰지 않는다. 영상 자체는 고칠 수 없으므로 수정본은 다시 녹음하거나 편집할 대본과 장면으로 쓴다.

## 2. 점검 순서

1. **금전 단어 스캔**: 제목, 표지, 파일명을 스캔한다. 나레이션과 본문은 파일로 스캔해 단서로 쓴다. `<이 스킬 폴더>`는 이 SKILL.md가 있는 폴더다.
   ```bash
   node "<이 스킬 폴더>/scripts/scan-money.mjs" --text "<제목>"
   node "<이 스킬 폴더>/scripts/scan-money.mjs" "<본문 파일>"
   ```
   Node.js가 없거나 실행되지 않으면 설치를 요구하지 말고, 돈, 원, 억, 매출, 수익, 가격, 값, 월급과 벌다, 수입, 통장, 정산, 금액 표현을 직접 찾아 계속 점검한다. 이 목록은 메타 규정이 아니라 **실제 제재 사례를 바탕으로 한 보수적인 경험 규칙**이다. 제목, 표지, 파일명에서 `strict`는 무조건 빼고, `extended`는 문맥을 보고 판단한다. `evasion`은 원래 단어로 되돌려 판단한다. 스캔 0건은 통과가 아니다. 스캐너는 단어만 찾고 주장은 판단하지 못한다.
2. **주장과 형식 점검**: [references/rules.md](references/rules.md)를 적용한다. 메타는 단어가 아니라 주장을 본다. 돈 단어를 지워도 "적은 노력으로 큰 결과"라는 약속이 남아 있으면 위험은 그대로다. 카드뉴스는 그 파일의 "카드뉴스" 절도 본다. 표지, 상단 문구, 댓글 키워드, 해시태그는 그 파일의 "삭제 사례에 많았던 위험 신호"도 본다.
3. **다른 주제 확인**: 아래 내용이 있으면 [references/other-rules.md](references/other-rules.md)의 해당 규정을 읽는다.
   - 실제 인물의 외모·성격 순위, 신체에 동그라미 표시, 실명 비판, 몰래카메라
   - 집단에 대한 일반화, 혐오, 폭력, 범죄 자랑, 위험한 챌린지
   - 자해, 극단적 다이어트, 시술·피·싸움 장면, 성적 표현
   - 미성년자, 독재자·범죄자 인용, 해킹·잠금 해제 방법

   아동을 성적으로 표현한 듯한 내용이 있으면 그 파일 맨 위의 멈춤 규칙을 먼저 따른다.

## 3. 등급과 근거

| 등급 | 뜻 |
|---|---|
| 🔴 삭제·게시 금지 | 규정이 삭제 대상이나 게시 금지로 적은 항목. 고치기 전에는 올리지 않는다 |
| 🟠 도달·연령 제한, 제재 가능 | 삭제까지는 아니어도 추천에서 빠지거나, 18세 이상으로 제한되거나, 제재받을 수 있다 |
| 🟡 확인 필요 | 규정 적용 여부 자체가 불분명함 |

사실 확인만 남은 항목(예: AI 레이블을 켤 계획인지)은 기본 등급을 유지하고 "이미 했다면 해결됨"이라고 조건을 적는다.

항목마다 근거의 종류도 밝힌다. 사용자가 확신의 정도를 알아야 고칠지 말지 정할 수 있고, 규정에 없는 말을 메타 규칙처럼 전하면 신뢰가 무너진다.

- **[규정 명시]** 문서에 조항이 있고, 이 문구가 그 조항에 그대로 해당함
- **[해석]** 문서 문구에서 내가 유추했거나, 조항을 이 문구에 넓혀 적용함
- **[경험]** 사용자의 과거 사례나 실제 삭제 사례. 메타가 공개한 기준은 아님

걸리지 않은 부분까지 경고하지 않는다. 경고가 많으면 정말 위험한 항목이 묻힌다.

## 4. 수정본 만들기

- **표현이 아니라 주장을 바꾼다.** "월 300 법니다"를 "월 삼백"으로 바꾸지 말고, 약속을 빼고 과정·이야기·호기심으로 옮긴다.
- **원래의 형식과 힘을 유지한다.** 대비, 놀라움, 사람(PD, 친구, 60대), 구체적인 장면을 쓴다. 사용자의 말투("여러분, ~")와 슬라이드 수도 그대로 둔다.
- **없는 사실을 지어내지 않는다.** 필요한 수치나 사례가 없으면 대괄호 칸으로 두고 물어본다.
- **걸리지 않은 문장은 건드리지 않는다.**
- **참여 조건을 없앤다.** 자료는 조건 없이 프로필 링크에 두고 한 문장으로 안내한다.

### 훅은 안전하면서도 강하게

사용자는 설명하듯 얌전한 훅을 원하지 않는다. 돈과 약속을 빼면 훅이 약해지기 쉬우니, 뺀 만큼 다른 힘으로 채운다. 훅을 고쳤거나 원래 훅이 약하면 후보 3개를 쓴다. 카드뉴스는 표지가 훅이다.

**원문의 뉘앙스를 먼저 지킨다.** 수정본에 넣는 1번 후보는 원문의 문장 구조, 대상, 약속의 방향을 그대로 두고 걸리는 단어만 바꾼 것이다. 예: "팔로워 0명이어도 첫 10만 원 버는 방법, 30초 안에 알려드리겠습니다" → "팔로워 0명이어도 첫 손님 받는 방법, 30초 안에 알려드리겠습니다". 아래 표의 힘으로 전혀 다르게 쓴 훅은 2·3번 대안으로만 제안한다.

**초보가 바로 이해할 쉬운 말을 쓴다.** "유료 고객", "의뢰", "수주"처럼 일하는 사람의 말은 어렵게 들려 진입장벽을 높인다. "첫 손님", "첫 일거리"처럼 일상어로 바꾼다.

| 쓸 힘 | 방향 | 예 |
|---|---|---|
| 뒤집기 | 다들 믿는 것을 뒤집는다 | "팔로워 많을수록 손해 보는 일" |
| 구체적인 장면 | 눈에 그려지는 대상을 짚는다 | "릴스 없는 동네 카페, 그게 첫 고객입니다" |
| 사람의 반응 | 누군가의 놀람이나 반대를 앞세운다 | "PD도 말이 안 된다고 했다" |
| 잃는 것 | 실제 실패나 후회를 먼저 말한다 | "팔로워 3만 계정이 날아갔습니다" |
| 궁금증 | 답을 바로 주지 않고 끊는다 | "사장님이 답장한 문장은 따로 있었습니다" |
| 짧은 명령 | 첫 행동을 바로 시킨다 | "편집 배우지 마세요" |

지킬 것:
- 돈 단어와 수입·결과 약속을 쓰지 않는다. "무조건", "누구나", "100%"로 힘을 내지 않는다.
- 사람의 반응, 실패담, 수치는 **실제 있었던 일일 때만** 쓴다. 원고에 없는 사실이면 대괄호로 두거나 "실제 있었던 일일 때만"이라고 표시한다.
- 영상이나 카드뉴스가 훅의 약속을 실제로 지켜야 한다. 내용과 다른 훅은 낚시성 콘텐츠로 추천에서 빠질 수 있다.
- 후보를 쓰면 스캐너로 돌려 본다. 12~20자 안팎의 짧은 문장을 먼저 고려한다.

이런 수정은 하지 않는다. 이유를 설명하고 내용을 바꾸는 대안을 준다.

- 초성·특수문자·띄어쓰기·이미지 속 글자로 표현을 감추기 (`ㄷㅗㄴ`, `수1익`). 글자를 이미지로 옮겨도 주장은 그대로다
- 심사 시스템과 사용자에게 다른 페이지를 보여주기
- 삭제된 콘텐츠를 제목이나 표현만 바꿔 다시 올리기. 걸린 주장과 장면을 바꿔 새로 만든 것만 돕는다
- 제재를 피하려 새 계정·부계정 만들기 (계정 무결성 위반, 그 계정도 삭제 대상)

표현만 숨기면 위반 내용은 그대로 남고, 회피 자체가 별도의 제재 사유가 될 수 있다.

## 5. 결과 형식

사용자는 문제 문구와 수정 전후를 표로 보기를 원한다. 판정 바로 다음에 이 표를 쓰고, 그 아래에 복사해서 쓸 전체본을 둔다.

```markdown
## 판정: 올리지 마세요 | 고친 뒤 올리세요 | 찾은 위험 없음
(한두 문장 요약)

## 수정 전후
| 등급 | 위치 | 수정 전 | 수정 후 | 문제와 근거 |
|---|---|---|---|---|

## 훅 후보
1. (수정본에 넣은 것) — 쓴 힘
2. …
3. …

## 수정본 전체
(릴스: 제목, 나레이션, CTA, 캡션 / 카드뉴스: 슬라이드 1, 슬라이드 2 … 캡션. 이미지에서 바꿀 요소도 적는다)

**채워 주실 칸**: 대괄호로 비운 사실을 묻는 질문. 없으면 생략

## 올릴 때 확인
(AI 레이블, 협찬 레이블, 음악, 링크 내용처럼 원고 밖에서 할 일)

## 못 본 것
(확인하지 못한 항목)
```

"수정 전후" 표는 위험한 순서로 쓴다. 판정은 이렇게 고른다.

- **올리지 마세요**: 위반이 콘텐츠의 핵심이라 고치면 내용이 바뀌는 경우 (수익 인증이 주제인 영상). 수정본은 새로 만드는 콘텐츠라고 표시한다.
- **고친 뒤 올리세요**: 주제는 그대로 두고 문구나 장면만 고치면 되는 경우. 모든 슬라이드를 고쳐야 해도 주제가 남으면 여기에 해당한다
- **찾은 위험 없음**: 찾은 항목이 없는 경우. "수정 전후", "수정본 전체", "올릴 때 확인"은 생략하고 "못 본 것"만 적는다. 훅이 약하면 "훅 후보"는 쓴다

[해석] 등급의 🟠는 사용자가 감수하고 유지할 수 있다. 위험과 얻는 것을 알려주고 선택은 맡긴다.
